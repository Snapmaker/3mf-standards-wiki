## 前言

本文讲解工程 `.3mf` 的必选部件 `Metadata/project_settings.config`。层高、速度、耗材、机器设置等工程级参数在保存时刻的全部生效取值，均记录于该文件。

本文说明该文件的作用（是什么、何时保存、怎么读取）、键类型构成（用户参数键三类与系统级固定键），并重点讲解系统级固定键的写入行为与触发条件。文件结构与取值形态的规范级定义见 [3mf 工程文件规范](3mf_standard.md) 6.3 与附录 D；本文为该规范的配套讲解文档，两者不一致时以规范为准。

## 引言

恢复一个切片工程，配置信息由三部分承载：全局参数基准（本文件）、对象与零件级参数覆盖（[model_settings.config](model_settings_config.md)）与预设来源差异（内嵌预设 `*_settings_N.config`）。本文件是其中唯一的全量层：以扁平键值形式记录保存时刻切片全部生效参数，实测约 500～600 键（584 项）。

本文件的键集由两类构成：用户在界面修改的工艺、耗材、打印机参数键（4.1，逐键语义见设置参数文档，本文不展开），与不由用户作为参数修改的系统级固定键（4.2 与第 5 章，本文重点）。

本文第 1 章划定范围；第 2 章定义术语；第 3 章说明文件的作用；第 4 章给出键类型总览；第 5 章详解系统级固定键；第 6 章说明取值形态与解析约定；第 7 章说明本文件在三层覆盖与内嵌预设体系中的位置；第 8 章汇总易混淆要点；深入阅读入口见文末附录。

## 1 范围

本文阐述 `Metadata/project_settings.config` 的文件作用、键类型构成与系统级固定键的写入行为，及其取值形态与在三层参数覆盖体系中的位置。

本文适用于需要读取、解析该文件，或排查其键集构成的读者。

本文不涉及：逐键的切片参数语义（分别见[工艺参数文档](../../settings/process/process_overview.md)、[耗材参数文档](../../settings/filament/filament_overview.md)、[打印机参数文档](../../settings/printer/printer_overview.md)）、对象与零件级覆盖的文件结构（见 [model_settings.config：对象与打印板信息](model_settings_config.md)）、内嵌预设的写出形态（见 [3mf 工程文件规范](3mf_standard.md) 6.4）、版本与兼容行为（见 [3MF 版本管理细则](3mf_version_management.md)）。

## 2 术语和定义

| 术语 | 定义 |
|---|---|
| 全局配置快照 | 保存工程时落盘的、切片时全部生效参数的扁平键值集合，为源码 `FullPrintConfig` 键集的序列化产物 |
| 头部元字段 | 正文键值之前的四个固定字段：`name` / `version` / `from` / `project_schema_version`（见 5.1） |
| 用户参数键 | 用户在界面修改的切片参数键，按所属预设域分工艺、耗材、打印机三类（见 4.1） |
| 系统级固定键 | 不由用户作为参数修改、由文件机制 / 机型 / 预设系统 / 运行状态决定的键（见 4.2 与第 5 章） |
| 无条件键 / 条件触发键 | 系统级固定键按写入行为的分类：前者每次保存必写，后者满足触发条件才写出（见 4.2） |
| 预设标识键 | 记录工程参数来源预设身份的四个键：`printer_settings_id` / `print_settings_id` / `filament_settings_id` / `filament_ids`（见 5.2） |
| 预设状态键 | 记录预设继承来源与用户修改状态的键：`inherits_group` / `different_settings_to_system`（见 5.3） |
| 三层覆盖 | project（本文件）/ object / part 三层的参数覆盖机制，本文件为全局基准层 |
| 序列化别名 | 落盘键名与源码定义名不一致的键，共 18 项（见 4.1） |
| 内嵌预设 | `Metadata/*_settings_N.config`，随包携带的预设差异文件，与本文件数据高度重复 |

## 3 文件的作用

### 3.1 是什么：全局参数基准的全量快照

本文件为工程 `.3mf` 的必选 JSON 部件（规范 6.3），是保存时刻切片全部生效参数的全量快照：正文为扁平键值对（值可为字符串或字符串数组，无嵌套对象），按键名字典序排列，所有标量与数组元素均为字符串，实测约 500～600 键（584 项）。结构示意（节选，`←` 注释为讲解所加）：

```text
{
  "name": "project_settings",           ← 头部元字段：文件身份，固定值
  "version": "2.4.0",                   ← 头部元字段：生成器软件版本，非格式版本
  "from": "project",                    ← 头部元字段：固定值
  "project_schema_version": "1",        ← 头部元字段：配置 schema 版本

  "layer_height": "0.2",                ← 正文：扁平键值，记录全部生效参数
  "filament_diameter": ["1.75"],        ← 数组元素仍为字符串（见第 6 章）
  "filament_retract_length": ["0.8"],   ← 序列化别名键，源码定义为 retract_*（见 4.1）
  …
}
```

在三层参数覆盖（第 7 章）中，本文件为 project（全局）层的基准：覆盖层未出现的键沿用本文件的全局值。参数溯源（"这些值从哪些预设来"）由预设标识键承担（5.2）。

### 3.2 何时保存：写入时机与内容来源

保存工程即写本文件。工程的三种保存路径（直接保存工程、通用导出、自动备份）共用同一导出链路，每次保存均写入，不存在"保存了工程但不带全局配置"的形态（保存策略与实测对照见规范附录 B；通用导出对 `Metadata/` 配置层原样带出，见规范 6.7）。

写入内容为保存瞬间的全量生效配置，由预设系统按下列来源叠加合成：

- 源码内置默认值（全量参数的基底，保证键恒在）；
- 当前选中的打印机、耗材与工艺预设（继承链合成后的取值，合成机制见 5.3 导语）；
- 工程板级状态（当前床型、擦拭塔位置、冲刷体积等，见 5.6）；
- 预设标识与状态键（保存前生成注入，见 5.2、5.3）。

序列化时不设内容过滤：合成结果按键名字典序全量写出。唯一的剔除发生在取值阶段——打印主机凭据类字段（`print_host`、`printhost_*` 共 7 项）在配置合成时即被移除，不进入本文件（实测样本均未见；规范另将其列为禁入，待定）。

### 3.3 怎么读取：主管线回读与直接解析

**主管线回读（打开工程）** 按以下时序执行：

1. 解包并解析本文件，逐键反序列化进配置对象。解析遇未知的字符串键即中止本文件后续键的处理，已解析键保留；错误仅记录日志，工程其余部件（几何、盘信息等）照常加载（加载失败语义详见 [3MF 版本管理细则](3mf_version_management.md) §7）。头部 `project_schema_version` 高于当前程序支持版本时，仅提示升级、不拦截（5.1）。
2. 按预设标识键（5.2）把工程挂载到所选的打印机 / 工艺 / 耗材预设，作为基线。
3. 按预设状态键（5.3）回放用户修改：清单外的键接受预设值覆盖，清单内的键保留工程值并标脏。
4. 重建参数界面，显示各预设的选中与已修改状态。

**直接解析（第三方工具 / 人工查阅）**：本文件为独立 JSON，可直接解析。取值形态约定见第 6 章（全字符串取值、数组长度语义等）。判读要义：正文即"选定预设 + 用户修改"的合成结果，用户修改键集合见 `different_settings_to_system`（5.3），参数来源预设见预设标识键（5.2）。

## 4 键类型总览

### 4.1 用户参数键：工艺、耗材、打印机三类

正文键集的主体是用户可在界面修改的切片参数，按所属预设域分三类：

| 类 | 所属预设域 | 键形与示例 |
|---|---|---|
| 工艺配置键 | 工艺预设 | 多为单值：`layer_height`、`sparse_infill_density`、`wall_loops`、速度 / 加速度族、支撑、裙边等 |
| 耗材配置键 | 耗材预设 | 多为逐槽数组（长度 = 耗材槽数）：`filament_diameter`、`nozzle_temperature_initial_layer`、`filament_flow_ratio` 等 |
| 打印机配置键 | 打印机预设 | 机器行为与限制：`machine_start_gcode`、`z_offset`、回抽族、`machine_max_*` 机器限制族等 |

三类键的逐键语义不在本文讲解，分别见[工艺参数文档](../../settings/process/process_overview.md)、[耗材参数文档](../../settings/filament/filament_overview.md)与[打印机参数文档](../../settings/printer/printer_overview.md)。

读取注意：18 个键的落盘名与源码定义名不一致（`filament_retract_*` 族在源码中定义为 `retract_*`；`machine_max_acceleration_*` / `machine_max_jerk_*` / `machine_max_speed_*` 共 12 项另行定义），读取时应按落盘名理解、不应按源码定义名查找。别名已由规范附录 D 正式登记；别名映射的维护机制与新增参数的统一别名规则待定。

### 4.2 系统级固定键：分组一览

系统级固定键指不由用户作为参数修改、由文件机制 / 机型 / 预设系统 / 运行状态决定的键，共七组：

| 组 | 键 | 写入行为 |
|---|---|---|
| 头部元字段与 schema 版本（5.1） | `name`、`version`、`from`、`project_schema_version` | 无条件必写 |
| 预设标识键（5.2） | `printer_settings_id`、`print_settings_id`、`filament_settings_id`、`filament_ids` | 无条件必写 |
| 预设状态与兼容性键（5.3） | `inherits_group`、`different_settings_to_system`、`print_compatible_printers`（另有 `compatible_machine_expression_group`、`compatible_process_expression_group` 机制同组） | **条件触发**，满足触发条件才写出 |
| 机器绑定键（5.4） | `printer_model`、`printer_variant`、`default_print_profile`、`default_filament_profile`、`default_bed_type`、`upward_compatible_machine` | 无条件必写（值由机型决定，可为空） |
| 机器派生几何与硬件键（5.5） | `printable_area`、`printable_height`、`nozzle_diameter`、`best_object_pos`、`start_end_points`、`head_wrap_detect_zone`、`bed_mesh_*`、`adaptive_bed_mesh_margin`、`bed_exclude_area`、`bed_custom_model`、`bed_custom_texture` | 无条件必写（值由机型决定） |
| 板级与项目状态键（5.6） | `curr_bed_type`、`wipe_tower_x`、`wipe_tower_y`、`flush_volumes_matrix`、`flush_volumes_vector` | 无条件必写 |
| 流量变体系统键（5.7） | `filament_flow_support`、`process_flow_support`、`printer_flow_support`、`filament_flow_step_size`、`nozzle_volume_type`、`filament_volume_type` | 无条件必写 |

边界说明：`gcode_flavor`、`nozzle_type`、`machine_max_*` 等键的取值随机型预设固定，但打印机设置页有对应输入字段，归入打印机配置键（4.1），不按系统级固定键对待。"条件触发"仅预设状态与兼容性一组；该组键在文件中未出现即触发条件未满足，属正常现象（5.3）。

## 5 系统级固定键详解

### 5.1 头部元字段与 schema 版本（无条件）

| 字段 | 值 | 说明 |
|---|---|---|
| `version` | 软件版本（如 `"2.4.0"`） | 生成器版本，非格式版本 |
| `name` | `"project_settings"` | 固定 |
| `from` | `"project"` | 固定 |
| `project_schema_version` | `"1"` | 配置 schema 版本；2.4.0 起落盘，缺失视为 legacy（维护规则待定） |

四字段无条件必写：前三者由序列化器固定写出；`project_schema_version` 以配置默认值（恒为 1）随全量键落盘，无任何运行时改写点。它是格式演进的预留机制，由源码的版本注册表维护（当前 current_version = 1）；读取端遇高于自身支持的版本时仅提示升级、不拦截；递增规则待定。

### 5.2 预设标识键（无条件）

工程保存时，当前使用的打印机、工艺与耗材预设的身份随参数快照一并落盘。四键每次保存强制写出（键恒在；`filament_ids` 的槽值可为空串——本地预设无云端标识时），且不计入用户修改清单、永不显示为已修改：

| 键 | 类型 | 语义 | 实测值示例 |
|---|---|---|---|
| `printer_settings_id` | 字符串 | 工程使用的打印机预设名 | `Snapmaker U1 (0.4 nozzle)` |
| `print_settings_id` | 字符串 | 工程使用的工艺预设名 | `0.24 Draft @Snapmaker U1 (0.4 nozzle)` |
| `filament_settings_id` | 字符串数组 | 各耗材槽使用的耗材预设名（逐槽） | `["Snapmaker TPU 95A HF @U1(…手机壳_MOSS 3D.3mf)", …]` |
| `filament_ids` | 字符串数组 | 各耗材槽的耗材标识（逐槽） | `["GFU99", "119531393501", …]` |

在参数覆盖体系中的作用：

- **不参与取值合成**：标识键不是参数、不进入任何覆盖层——正文键值已是"选定预设 + 用户修改"合成后的全量结果，标识键回答的是"这些值从哪些预设来"。
- **恢复预设关联**：回读工程时据标识键把工程重新挂载到所选预设（3.3 第 2 步），使复切沿用同一预设基准。
- **参数溯源**：以官方预设解析继承链为基线，可将全量值分解为"预设基准 + 用户修改"（嵌入预设 − 官方预设链 = 用户真实修改量）；标识键指明应与哪条预设链对照。预设相对父预设的差异本体由内嵌预设携带（第 7 章）。

其余约定：

- `filament_settings_id` 与 `filament_ids` 为逐槽数组，长度随耗材槽数变化，解析不应写死长度（第 6 章数组约定）。
- 实测 `filament_settings_id` 的预设名可内嵌来源工程的文件名（上例括号内的 `…_MOSS 3D.3mf`），系导入外来工程后复制预设继承所致，属预设元数据污染面（待定）。
- `filament_ids` 实测值呈两种形态：材料短码（如 `GFU99`）与云端数字标识（如 `119531393501`），与预设文件的身份键 `setting_id`（如 `GFSB99`）属同一标识体系；预设侧讲解见 [打印配置文件命名与继承规范](../../preset/configuration_files.md)。
- SLA 流程存在同族键 `sla_material_settings_id` / `sla_print_settings_id`，属 SLA 专用字段，FDM 工程不落盘。

### 5.3 预设状态与兼容性键（条件触发）

参数的取值合成与覆盖分属两套体系：

- **预设系统的继承覆盖（保存前）**：预设文件本身是相对父预设的差异文件，取值沿继承链回退（子预设 > 父预设 > 源码内置默认值），用户修改叠加其上；
- **工程文件的三层覆盖（保存后）**：part > object > project，本文件正文为 project 层基准（第 7 章）。

保存工程时，第一套体系的合成结果被扁平化为全量键值，写入本文件正文：

```text
选定预设（来源由标识键记录）+ 用户修改
        ▼  继承链取值：子预设 > 父预设 > 源码内置默认
合成后的全量生效值 ──扁平落盘──▶ 本文件正文（project 层基准）
```

本组键记录第一套体系的状态，写入采用同一判定：**任一预设槽位非空才写出整键，全空则键不出现**。槽位布局固定为 `[0]` 工艺、`[1..n]` 各耗材槽、`[n+1]` 打印机（无人值守的命令行保存路径例外：状态键恒写出，可为全空数组）。

| 键 | 类型 | 触发条件 | 槽位值 |
|---|---|---|---|
| `different_settings_to_system` | 字符串数组 | 至少一个所选预设相对其父系统预设存在被修改的键 | 该预设被修改键名的清单（分号分隔） |
| `inherits_group` | 字符串数组 | 至少一个所选预设为带继承父的副本（含未修改过取值的复制预设） | 该预设的父预设名；直接选用系统预设的槽位为空串 |
| `print_compatible_printers` | 字符串数组 | 工艺预设声明了兼容打印机列表 | 兼容打印机名列表（实测如 `["Snapmaker U1 (0.4 nozzle)"]`） |
| `compatible_machine_expression_group` / `compatible_process_expression_group` | 字符串数组 | 预设声明了兼容条件表达式 | 条件表达式（实测样本未出现） |

修改清单的计算不含 `inherits` 与三个 `*_settings_id` 标识键（标识键永不计入用户修改，5.2）。实测形态：`different_settings_to_system` 如 `["bottom_shell_layers;brim_type;default_acceleration;…"]`；`inherits_group` 多为空串、仅个别槽位非空（如 `["", …, "Snapmaker TPU 90A @U1", …]`）——只要任一所选预设是"基于系统预设的副本"，整键即写出，这是实测"多数槽位为空但键存在"的原因。

**回读重放流程（主管线现状）**——两状态键共同决定"预设演进之后，用户的哪些修改被保留"：

1. 打开工程，按标识键（5.2）挂载所选预设；`inherits_group` 逐槽提供各预设的继承父，指定覆盖基准预设（无继承父时按同名系统预设）。
2. **不在清单中的键**接受基准预设值覆盖——预设在工程保存后若已更新，生效的是更新后的预设值；清单缺失视为无用户修改、全量接受覆盖。
3. **在清单中的键**保留工程保存时的取值、不被预设覆盖；随后按"工程值 vs 基准预设"的真实取值差在设置界面显示已修改（标脏）——覆盖后与预设完全一致的键不标脏。

用户修改若未记入清单，重开工程时将被预设值覆盖。第三方解析工具可据该清单直接得到"用户修改键"集合（主管线回读即按它执行）；本组键在文件中缺省表示触发条件未满足，不应视为异常。

**定性说明**：状态键曾按"预设系统内部"语义被记为泄漏，规范草案一度沿用"不应写入"表述；实际二者为条件触发的固定系统字段，属正常落盘项，该定性已作废。

**同版本比对**：7 样本实测，同版本样本之间本文件的差异仅来自本组条件键，其余键值一致；同版本文件比对时可先剔除。

### 5.4 机器绑定键（无条件，值由机型决定）

六个键随打印机预设携带，键恒写（机型未提供时为空值），用户界面无输入字段（仅预设描述展示）：

| 键 | 类型 | 语义 | 实测示例 |
|---|---|---|---|
| `printer_model` | 字符串 | 机型身份标识，预设解析与机型匹配用 | `Snapmaker U1` |
| `printer_variant` | 字符串 | 机型变体档位（喷嘴档） | `0.4` |
| `default_print_profile` | 字符串 | 切换到该机型时默认选用的工艺预设 | 随机型预设声明 |
| `default_filament_profile` | 字符串数组 | 切换到该机型时默认选用的耗材预设 | 随机型预设声明 |
| `default_bed_type` | 字符串 | 默认床型，`curr_bed_type`（5.6）的初始种子 | 随机型预设声明 |
| `upward_compatible_machine` | 字符串数组 | 机型向上兼容表 | U1 实测为空数组；多耗材快切机型会非空（机型相关） |

这组键回答"工程当时的机器环境是什么、默认配置落在哪"：读取端据 `printer_model` / `printer_variant` 识别机型，据三个 `default_*` 播种初始预设选择与床型。

### 5.5 机器派生几何与硬件键（无条件，值由机型决定）

机器固有的几何与硬件参数，值随机型预设整体更换（部分键在打印机设置页有字段，但系统预设未解锁时只读）：

| 键 | 类型 | 语义 |
|---|---|---|
| `printable_area` | 点列表 | 可打印区域（床面多边形），点列表形态见第 6 章 |
| `printable_height` | 数值 | 最大打印高度（mm） |
| `nozzle_diameter` | 数值数组 | 各挤出机喷嘴直径（逐挤出机，实测如 `["0.4"]`） |
| `best_object_pos` | 点 | 自动排列的基准摆放位 |
| `start_end_points` | 点列表 | 换料起止点，由换料 G-code 派生（只读） |
| `head_wrap_detect_zone` | 点列表 | 打印头环绕检测区（机型相关，可为空） |
| `bed_mesh_min` / `bed_mesh_max` | 点 | 床网域下界 / 上界 |
| `bed_mesh_probe_distance` | 点 | 床网探针间距 |
| `adaptive_bed_mesh_margin` | 数值 | 自适应床网边距 |
| `bed_exclude_area` | 点列表 | 床面禁打区 |
| `bed_custom_model` / `bed_custom_texture` | 字符串 | 床面自定义模型 / 纹理的包内资源路径（可为空串） |

与 5.4 的区别：5.4 是机型身份与默认选择的"指针"，本组是机型固有的"尺寸与硬件参数"；两者均无条件必写、值由机型决定，换机型即整体更换。

### 5.6 板级与项目状态键（无条件）

五个键来自工程状态容器（工程配置专属键集），记录当前工程的板级与项目状态，每次保存必写：

| 键 | 类型 | 语义 | 来源与修改入口 |
|---|---|---|---|
| `curr_bed_type` | 枚举 | 当前床型 | 机型默认床型播种，界面床型下拉可改（限机型支持枚举）；实测如 `Textured PEI Plate` |
| `wipe_tower_x` / `wipe_tower_y` | 数值数组 | 擦拭塔位置（每盘一值） | 切片 / 排版管线自动计算，场景中可拖拽 |
| `flush_volumes_matrix` | 数值数组 | 多耗材换色冲刷矩阵（n 耗材为 n×n） | 装机时装载机器冲刷数据，冲刷体积对话框可改 |
| `flush_volumes_vector` | 数值数组 | 装料 / 卸料冲刷体积 | 同上 |

冲刷两键的数组长度随耗材槽数变化（n 耗材时矩阵为 n² 项），解析不应写死长度（第 6 章数组约定）。

### 5.7 流量变体系统键（无条件）

切片软件流量变体（flow variant）预设体系的内部键，每次保存必写：

| 键 | 类型 | 语义 |
|---|---|---|
| `filament_flow_support` / `process_flow_support` / `printer_flow_support` | 字符串数组 | 预设声明的流量变体支持（默认 `standard`） |
| `filament_flow_step_size` | 整数数组 | 各耗材的变体档数，运行时计算 |
| `nozzle_volume_type` | 枚举 | 喷嘴容积档，机器硬件上报，喷嘴下拉可改 |
| `filament_volume_type` | 枚举数组 | 各耗材的流量档选择 |

这组键属预设系统内部状态，第三方解析无需处理，原样保留即可。

## 6 取值形态与解析约定

本文件所有标量与数组元素均为字符串，不存在原生 JSON number / bool / null——解析器不应以 JSON 类型推断键语义。取值形态与规范 [§6.3](3mf_standard.md#63-全量配置快照metadataproject_settingsconfig) 一致，以规范为准：

| 形态 | 写法示例 | 约定 |
|---|---|---|
| 数值 | `"3"`、`"0.2"` | 按字段含义转数字 |
| 布尔 | `"0"` / `"1"` | 与数值同形二义，须按键名语义区分 |
| 百分比 | `"15%"` | 不与绝对值混同 |
| 数组 | `["200","220"]` | 元素仍是字符串；可空字段可含 `"nil"`（≠ 0）；**长度有语义且随机型变化**，解析不应写死长度 |
| 点 / 点列表 | `"10,20"` / `["0x0","270x0"]` | 单点逗号分隔；点列表每项以 `x` 分隔 |
| 枚举 / G-code 片段 | `"monotonic"` | 按原样字符串处理 |
| 空字符串 / 空数组 | `""`、`[]` | 与 `"nil"` 是两种"空" |
| 元素内嵌换行 | `["0,0", "\n0.2,0.4444"]` | 解析前先 trim |

## 7 在三层覆盖与内嵌预设中的位置

本文件为三层参数覆盖的全局基准层：

| 层 | 载体 | 语义 |
|---|---|---|
| project（全局） | `project_settings.config`（本文件） | 工程级基准值 |
| object（对象覆盖） | [model_settings.config](model_settings_config.md) 对象节 | 该对象全部实例生效 |
| part（零件覆盖） | [model_settings.config](model_settings_config.md) 零件节 | 仅该零件生效 |

- 生效值按 **part > object > project**（零件 > 对象 > 全局）合成；该规则仅存在于读取代码逻辑中，文件本身无任何声明（待定）。
- 本文件为全量快照，覆盖层为稀疏差异：覆盖层未出现某键 ≠ 值为空，而是未修改、沿用本文件的全局值。
- 覆盖键集合为本文件键集的子集（实测对象层 32 种、零件层 17 种）。
- 内嵌预设 `*_settings_N.config` 与本文件数据约 95% 重复（双写）；恢复工程时按各自用途读取，不应把包内最后一个配置文件当作最终配置——两者不一致时谁生效现状未定义（待定）。
- 本文件的用途：参数回读、复切、问题排查。

## 8 易混淆要点速查

1. **`version` 不是格式版本**：头部 `version` 是生成器软件版本；格式演进的载体是 `project_schema_version`。预设文件的 `version`、软件 `version` 与 `project_schema_version` 是三套互不相干的版本号（待定）。
2. **系统固定键"未出现"分两种情形**：条件触发组（5.3）未出现 = 触发条件未满足，属正常；无条件组未出现才属异常。
3. **布尔与数值同形**：`"0"` / `"1"` 既可为布尔亦可为数值，须按键名语义区分；文件中不存在原生 JSON 布尔值。
4. **`"nil"` ≠ 空串 ≠ 0**：空字符串 / 空数组与 `"nil"` 是两种"空"；数组中的 `"nil"` 表示该槽位无值，不等于数值 0。
5. **数组长度有语义且随机型 / 槽数变化**（逐槽耗材键、冲刷矩阵等），解析不应写死长度。
6. **落盘名 ≠ 源码定义名**：18 项序列化别名（`filament_retract_*` ↔ `retract_*` 等），读取按落盘名理解（见 4.1）。
7. **机器绑定 / 派生键"值随机型、键恒写"**：`printer_model`、`printable_area` 等值由机型预设决定，机型未提供时为空值而非键缺失（见 5.4、5.5）。
8. **内嵌预设高度重复**：与本文件数据约 95% 重复，不应把包内最后一个配置文件当作最终配置。
9. **预设标识键记录"来源"而非"取值"**：`printer_settings_id` 等四键标识工程参数来自哪些预设；参数本体在正文键值中，预设差异在内嵌预设（见 5.2）。
10. **两状态键职能不同**：`inherits_group` 逐槽记录继承父、回读时指定覆盖基准预设；`different_settings_to_system` 记录用户修改键清单、回读时保全清单内取值并标脏（见 5.3）。
